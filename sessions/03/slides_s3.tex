\begin{frame}{Why a Collection Is Silently Incomplete}

\small
\begin{itemize}
    \setlength{\itemsep}{6pt}
    \item \textbf{Pagination}: the API returns 100 results per page; the script read the first page.
    \item \textbf{Rate limits}: request 412 got a \texttt{429}; the script skipped it and went on.
    \item \textbf{Missing items}: you asked for 12 documents; the answer lists 2 as missing. Nobody read that field.
    \item \textbf{Versions}: the provider corrected the data last month; your colleague downloaded before.
    \item \textbf{Filters you did not choose}: a default language, period or country in the endpoint.
\end{itemize}

\vspace{0.4cm}

\textbf{None of these raises an error.} The script ends; the agent reports success; the data are wrong.

\end{frame}

\begin{frame}{Last Week's Question, Answered}

\small
\textbf{Four checks, written into the collector}

\vspace{0.1cm}
\begin{enumerate}
    \setlength{\itemsep}{5pt}
    \item \textbf{Accounting.} Requested = returned + listed as missing. Nothing silently dropped.
    \item \textbf{Content.} No empty record, no duplicate, every field you need present.

\end{enumerate}

\textbf{And archive the raw answers} before any processing, with the version and a log of every request. If a check fails in a month, you can find out why.

\sectionslide{Part 2. Annotating Through an LLM API}{The same door, a different provider}

\begin{frame}{Why Annotate with an LLM}

\footnotesize
\textbf{Why it caught on}
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item Zero-shot ChatGPT beat crowd workers on four of five tasks, for a fraction of the cost (Gilardi, Alizadeh and Kubli 2023, \textit{PNAS}, here at UZH).
    \item GPT-4 beat expert coders and supervised classifiers on political tweets (T\"ornberg 2025); few-shot prompts matched supervised methods (Ornstein et al.\ 2025).
    \item On manifestos, LLM positions correlate around 0.9 with expert surveys (Le Mens and Gallego 2025; Benoit et al.\ 2026, \textit{AJPS}).
\end{itemize}

\vspace{0.15cm}

\textbf{Why it needs validation}
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item Zero-shot models do not beat fine-tuned ones at classification (Ziems et al.\ 2024).
    \item Small open models follow codebooks poorly, and worst of all on Manifesto data (Halterman and Keith 2026, \textit{Political Analysis}).
    \item Answers change with the wording of the prompt, and on a simple rerun (Reiss 2023; Barrie, Palaiologou and T\"ornberg 2026).
    \item Labels at 80--90\% accuracy still bias a regression that uses them, unless corrected with a gold sample (Egami et al.\ 2023).
\end{itemize}

\vspace{0.1cm}
\centering
\alert{Cheap labels, expensive validation.}

\end{frame}

    \setlength{\itemsep}{3pt}

    \item \textbf{A schema, not free text.} The model must return valid JSON with one of eight labels: no parsing, no ``I think it is probably\dots''.

\end{itemize}

\begin{frame}[fragile]{One Call, in Code}

    model="claude-haiku-5-5",         # pinned snapshot: report it
    max_tokens=300,

    messages=[{"role": "user",

\begin{frame}{Reproducibility with a Closed Model}

\small
\begin{itemize}
    \setlength{\itemsep}{6pt}
    \item \textbf{Pin the model.} \texttt{claude-haiku-5-5} names one snapshot; Anthropic does not change its weights. Report the ID, never ``Claude''.
    \item \textbf{You cannot fix the randomness.} The current Claude models do not accept \texttt{temperature}; OpenAI's reasoning models neither, and its \texttt{seed} is deprecated. So: run twice, and report how many answers change.
    \item \textbf{The serving can still change}, even with the same weights; and a model ID is retired one day. Your archived answers are the record, not the model.
    \item \textbf{Archive everything}: the prompt file, the schema, the parameters, every raw answer, the date. That is the reproducibility bundle of Session 2, in Part 7 of the notebook.
    \item \textbf{The model may have seen your data.} Manifestos are on the web; the model may have read them, and even their codes, in training. A held-out or new corpus is the honest test.
\end{itemize}

\end{frame}

\begin{frame}{Validation: Four Numbers, Not One}

\small
\begin{enumerate}
    \setlength{\itemsep}{6pt}
    \item \textbf{Agreement with careful human coding}: accuracy, macro-F1, Cohen's $\kappa$ (agreement corrected for chance). Read the confusion matrix, not only the number.
    \item \textbf{Stability}: the same items, a second run. How many answers change?
    \item \textbf{Your own agreement with the coders}, on 15 sentences. If you agree with them only 60\% of the time, a model at 70\% is not bad: the task is hard.
    \item \textbf{The aggregate your paper reports}: each party's share of welfare statements, computed from the coders and from the model. Sentence-level errors can cancel out, or pile up in one direction.
\end{enumerate}

\vspace{0.3cm}

{\footnotesize \textbf{The benchmark is a coder, not the truth.} Trained Manifesto coders recoding the same text agreed with the master coding at $\kappa$ of about 0.3 to 0.5 on the 56 categories (Mikhaylov, Laver and Benoit 2012). Seven domains are easier; and each French election was coded by one person.}

\end{frame}

\sectionslide{Part 3. A Model on Your Own Machine}{Same task, same code, nothing leaves your laptop}

\begin{frame}{Why Run a Model Locally}

\footnotesize
\begin{columns}[T]
\column{0.48\textwidth}
\textbf{For}
\begin{itemize}
    \setlength{\itemsep}{4pt}
    \item \textbf{Confidential data stays on your machine}: interviews, open survey answers, records. Often the only option a data agreement allows.
    \item \textbf{Free per call}: a million sentences cost electricity and time, not money.
    \item \textbf{Exact replication}: you can archive the weights themselves, and cite their digest.
    \item \textbf{Temperature and seed work}: same input, same answer, on the same machine.
\end{itemize}

\column{0.48\textwidth}
\textbf{Against}
\begin{itemize}
    \setlength{\itemsep}{4pt}
    \item \textbf{Smaller, so less accurate}, above all on hard codebooks (Halterman and Keith 2026).
    \item \textbf{Slower}, without a good GPU: seconds per sentence, not milliseconds.
    \item \textbf{Your hardware decides} which model you can run.
    \item \textbf{You maintain it}: versions, disk space, memory.
\end{itemize}
\end{columns}

\vspace{0.3cm}
\centering
{\small The middle way: a large open model on the UZH cluster (Part 4).}

\end{frame}

\begin{frame}[fragile]{Ollama in Five Commands}

\footnotesize
\begin{columns}[T]
\column{0.6\textwidth}
{\scriptsize
\begin{verbatim}
# macOS, Windows: ollama.com/download
# Linux:
curl -fsSL https://ollama.com/install.sh | sh

ollama pull ministral-3:8b    # once: 6 GB
ollama run ministral-3:8b "Bonjour"
ollama ps     # loaded? GPU or CPU?
ollama list   # ID = start of digest
\end{verbatim}}

\column{0.38\textwidth}
\begin{itemize}
    \setlength{\itemsep}{4pt}
    \item \textbf{A server on your laptop}: \texttt{localhost:11434}, with its own API and the OpenAI format (\texttt{/v1}).
    \item \textbf{Structured output}: \texttt{format=} a JSON schema, the same as for Claude.
    \item \textbf{Free, open source} (MIT), on macOS, Windows, Linux.
\end{itemize}
\end{columns}

\vspace{0.15cm}

\textbf{Two traps}
\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item \textbf{Context}: on machines with less than 24 GB, the default is 4,096 tokens. Longer texts are cut silently: set \texttt{num\_ctx}.
    \item \textbf{Cloud models} (tags ending in \texttt{cloud}) run on Ollama's servers, mostly in the US: your text leaves the machine. Switch them off: \texttt{OLLAMA\_NO\_CLOUD=1}.
\end{itemize}

\end{frame}

\begin{frame}{Which Model for Your Machine}

\footnotesize
\textbf{Rule of thumb}: at 4 bits (the usual \texttt{Q4\_K\_M}), about \textbf{0.6 GB per billion parameters}, plus 1 to 3 GB. On a Mac, the model shares memory with everything else.

\vspace{0.2cm}
\centering
{\footnotesize
\renewcommand{\arraystretch}{1.15}
\begin{tabular}{@{}l>{\raggedright\arraybackslash}p{8.2cm}@{}}
\toprule
\textbf{Your machine} & \textbf{Ollama tags (download size)} \\
\midrule
8 GB & \texttt{ministral-3:3b}, \texttt{qwen3.5:4b}, \texttt{gemma4:e2b} \\
16 GB & \texttt{ministral-3:8b} (6.0 GB, today's default), \texttt{qwen3.5:9b} (6.6 GB), \texttt{gemma4:12b} (8.0 GB) \\
32 GB & \texttt{mistral-small3.2:24b} (15 GB), \texttt{qwen3.5:27b} (17 GB), \texttt{gemma4:26b} (18 GB, fast: 4B active) \\
Colab, T4 (16 GB) & up to about 12 GB: \texttt{gemma4:12b}, \texttt{ministral-3:14b} (9.1 GB) \\
Cluster, L4 (24 GB) & 26--27B models; 70B on an A100 or H100 (80 GB) \\
\bottomrule
\end{tabular}}

\vspace{0.2cm}
\raggedright
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item \textbf{French texts}: Ministral (Mistral, Paris), Qwen 3.5 (201 languages) and Gemma 4 (140+) all list French.
    \item \textbf{Start small, then go up}: if the 8B is far from Claude on your validation sample, try the 24--27B before you give up on local.
\end{itemize}

\vspace{0.05cm}
{\scriptsize Sizes from the Ollama library, 3 November 2026. The fit by machine is a guide, not a guarantee.}

\end{frame}

\begin{frame}{Other Ways to Run a Model Locally}

\footnotesize
\begin{itemize}
    \setlength{\itemsep}{5pt}
    \item \textbf{LM Studio}: an app with a model browser and a chat; serves the OpenAI format on \texttt{localhost:1234}. Free, also for work. The easiest start if you dislike terminals.
    \item \textbf{llama.cpp}: the engine under most of these tools (MIT). \texttt{llama-server} serves any GGUF file from Hugging Face, with schema-constrained output.
    \item \textbf{MLX} (\texttt{mlx-lm}): Apple's framework, the fastest on Apple Silicon. Ollama and LM Studio can use it.
    \item \textbf{vLLM}: for GPU servers and clusters, many requests in parallel, OpenAI format (Apache 2.0). The tool for a whole corpus on the ScienceCluster.
    \item \textbf{Hugging Face \texttt{transformers}}: any model of the Hub, in Python. The most control, the most setup; also the way to fine-tune your own classifier.
    \item \textbf{Jan}: an offline chat app, open source.
\end{itemize}

\vspace{0.2cm}
\centering
\small Start with Ollama or LM Studio. Move to vLLM when you have a GPU node and a corpus.

\end{frame}

\begin{frame}{Open Weights Is Not Open}

\small
\textbf{Open weights}: you can download the model and run it; its licence says what you may do with it.
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item Apache 2.0: Gemma 4, Qwen 3.5, Ministral 3 and Mistral Small, gpt-oss
    \item Llama: Meta's own community licence, with conditions; open weights, not open source
\end{itemize}

\vspace{0.25cm}

\textbf{Fully open}: the weights, \emph{and} the training data, the code and the recipe.
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item \textbf{Apertus}, the Swiss model (EPFL, ETH Zurich, CSCS): version 1.5 in July 2026, 8B and 70B, Apache 2.0. On Hugging Face; in Ollama only as community builds.
    \item OLMo (Allen Institute for AI)
\end{itemize}

\vspace{0.25cm}

\textbf{Why a researcher should care}
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item With the training data public, you can check whether the model saw your corpus, and perhaps its codes. With any other model, you cannot.
    \item A licence can forbid uses, or change with the next version (Gemma moved to Apache 2.0 with Gemma 4).
\end{itemize}

\end{frame}

\begin{frame}{Reporting a Local Model}

\small
\textbf{What goes in the paper's appendix}
\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item The tag (\texttt{ministral-3:8b}) \emph{and} the digest: a tag can point to new weights tomorrow, the digest cannot
    \item The quantization (\texttt{Q4\_K\_M}, about 4.9 bits per weight): a different quantization is a different model
    \item The runtime and its version (\texttt{ollama -v}), and the hardware
    \item The options: temperature, seed, context length, thinking on or off
\end{itemize}

\vspace{0.3cm}

\textbf{If the paper depends on it, archive the weights file} (in \texttt{\textasciitilde/.ollama/models/blobs}), or use a file from Hugging Face pinned to one commit. Ollama cannot yet guarantee a download by digest.

\vspace{0.3cm}

\textbf{Part 7 of the notebook} writes the tag, the digest, the quantization and the options to \texttt{params.json}.

\end{frame}

\begin{frame}[fragile]{Same Code, Any Backend}

\small
Ollama, LM Studio, llama.cpp, vLLM and most commercial providers speak the same format (OpenAI's chat completions). Only three lines change.

\vspace{0.15cm}
{\scriptsize
\begin{verbatim}
from openai import OpenAI

# Ollama
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
# LM Studio:      "http://localhost:1234/v1"
# vLLM, GPU node: "http://localhost:8000/v1"
# Mistral (EU):   "https://api.mistral.ai/v1", with your key

r = client.chat.completions.create(
    model="ministral-3:8b",
    messages=[{"role": "system", "content": CODEBOOK},
              {"role": "user", "content": "TARGET: ..."}],
    response_format={"type": "json_schema", "json_schema":
                     {"name": "annotation", "schema": SCHEMA, "strict": True}},
    temperature=0, seed=2026)
\end{verbatim}}

\vspace{0.1cm}
{\footnotesize In the notebook: \texttt{make\_openai\_annotator(base\_url, model)}, Part 5.}

\end{frame}

\begin{frame}{Why a Cluster}
