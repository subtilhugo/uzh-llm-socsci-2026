\begin{frame}{Three Kinds of API You Will Meet}
\small
\renewcommand{\arraystretch}{1.4}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{3.2cm}>{\raggedright\arraybackslash}p{3.6cm}>{\raggedright\arraybackslash}p{4.4cm}@{}}
\toprule
& \textbf{You send} & \textbf{You get back} \\
\midrule
\textbf{A data API} \newline {\footnotesize INSEE, Manifesto, OpenAlex, a parliament} & a query: units, period, fields & \textbf{data}: a table or documents, the same for everyone \\
\textbf{A model API} \newline {\footnotesize Claude, OpenAI, Mistral, your own Ollama} & your text and your instructions & \textbf{a judgement}: a label, a summary; billed per token \\
\textbf{An MCP server} \newline {\footnotesize a connector of your agent} & nothing: the agent calls it & \textbf{a tool the agent can use}: read your Drive, query a database, call a data API \\

\end{tabular}

Today: the first two, in code. The third is how your agent reaches them without you writing the code.

    \item The limits: requests per day, results per page.

\begin{frame}{The Model API: Labelling}
\small
\textbf{Same door, a different answer.} You send a sentence and a codebook; the model sends back a label.

\vspace{0.4cm}
\begin{itemize}
    \setlength{\itemsep}{5pt}
    \item \textbf{Paid per token}: the codebook, the sentence, the answer. A few cents per thousand sentences with a small model.
    \item \textbf{Not the same for everyone}: the answer can change between runs and between model versions.
    \item \textbf{Your data leave your machine.} Confidential texts: a local model (Part 3) or the cluster (Part 4).
    \item \textbf{Needs validation}: the label is a claim, not a fact. Part 2.
\end{itemize}

\vspace{0.4cm}
Claude today; OpenAI, Mistral, Gemini work the same way, with the same Python code.
\end{frame}

\begin{frame}{The MCP Server: Giving the Agent a Tool}
\small
\textbf{Model Context Protocol}: a standard for connecting tools to an agent. The agent sees a list of tools and calls them itself.

\vspace{0.4cm}
\begin{itemize}
    \setlength{\itemsep}{5pt}
    \item Your agent with a Google Drive connector: ``find the survey codebook in my Drive''.
    \item With a database connector: ``how many rows per wave?''.
    \item With a data API wrapped as a server: ``download the 2022 municipal population''.
\end{itemize}

\vspace{0.4cm}
\textbf{Not today in code.} Today you write the request yourself, so that you know what the agent does when it calls a tool for you.
\end{frame}

\begin{frame}{Keys}
\begin{enumerate}
    \setlength{\itemsep}{8pt}
    \item Never in the code: \texttt{.env} on your laptop, Secrets in Colab.
    \item Never in git: \texttt{git check-ignore .env}.
    \item Never on a shared screen, in a chat, in a prompt.
    \item Cap what a key can spend. Today's key has a cap.
    \item Leaked? Revoke it, make a new one.
\end{enumerate}

\vspace{0.5cm}
\centering
A key is a password that spends money.
\end{frame}

\begin{frame}{Why a Collection Is Silently Incomplete}
\begin{itemize}
    \setlength{\itemsep}{7pt}
    \item \textbf{Pagination}: 100 results per page; the script read page one.
    \item \textbf{Rate limits}: request 412 got a 429; the script went on.
    \item \textbf{Missing items}: the answer lists two documents as missing. Nobody read that field.
    \item \textbf{Versions}: the provider corrected the data last month.
    \item \textbf{Hidden defaults}: a language, a period, a country you did not choose.
\end{itemize}

\vspace{0.5cm}
None of these raises an error.
\end{frame}

\begin{frame}{The Answer: a Number You Did Not Produce}
\small
\begin{enumerate}
    \setlength{\itemsep}{6pt}
    \item \textbf{Accounting.} Requested $=$ returned $+$ listed as missing.
    \item \textbf{Content.} No empty record, no duplicate.
    \item \textbf{A published total.} The core dataset gives each manifesto's number of quasi-sentences. Count ours.
    \item \textbf{A published statistic, recomputed.} The share of welfare statements (\texttt{per504}), from the texts.
\end{enumerate}

\vspace{0.4cm}
And archive every raw answer before processing, with the version.

\vspace{0.5cm}
\centering

\end{frame}

\sectionslide{Part 2. Annotating Through an API}{Cheap labels, expensive validation}

\begin{frame}{Why Annotate with an LLM}
\small
\textbf{Why it caught on}
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item ChatGPT beat crowd workers on four of five tasks, for a fraction of the cost (Gilardi, Alizadeh and Kubli 2023, UZH).
    \item GPT-4 beat expert coders on political tweets (T\"ornberg 2025).
    \item On manifestos, LLM positions correlate around 0.9 with expert surveys (Le Mens and Gallego 2025; Benoit et al.\ 2026).
\end{itemize}

\vspace{0.3cm}
\textbf{Why it needs validation}
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item Small open models follow codebooks poorly, worst of all on Manifesto data (Halterman and Keith 2026).
    \item Answers change with the wording of the prompt, and on a rerun (Reiss 2023).
    \item Labels at 85\% accuracy still bias a regression, unless corrected with a gold sample (Egami et al.\ 2023).
\end{itemize}
\end{frame}

\centering

\vspace{0.5cm}
\raggedright
\begin{itemize}
    \setlength{\itemsep}{4pt}
    \item The codebook is the method: a file, versioned, in your appendix.
    \item A schema, not free text: valid JSON, one of eight labels.
    \item A reason before the label: you read it when you disagree.
    \item Every answer appended to a file: a rerun never pays twice.
\end{itemize}

\begin{frame}[fragile]{One Call}
\scriptsize
\begin{verbatim}
class Annotation(BaseModel):
    reason: str
    domain: Literal["external_relations", "freedom_democracy",
                    "political_system", "economy",
                    "welfare_quality_of_life", "fabric_of_society",
                    "social_groups", "no_category"]

r = claude.messages.parse(
    model="claude-haiku-5-5",         # a pinned snapshot: report it
    max_tokens=300,
    system=[{"type": "text", "text": CODEBOOK,
             "cache_control": {"type": "ephemeral"}}],   # same each call: cached
    messages=[{"role": "user", "content": "PREVIOUS: ...\nTARGET: ..."}],
    output_format=Annotation,         # the answer must fit the schema
    thinking={"type": "disabled"},    # a short task: no thinking
)
r.parsed_output.domain, r.usage
\end{verbatim}

\small
Read one full response before you run 200.
\end{frame}

\begin{frame}{Reproducibility with a Closed Model}
\small
\begin{itemize}
    \setlength{\itemsep}{8pt}
    \item \textbf{Pin the model}: \texttt{claude-haiku-5-5} names one snapshot. Never ``Claude''.
    \item \textbf{You cannot fix the randomness}: no temperature, no seed on current models. Run twice, report what changed.
    \item \textbf{Archive everything}: prompt, schema, parameters, every raw answer, the date. The model will be retired; your archive stays.
    \item \textbf{The model may have seen your data}: manifestos are on the web. A new corpus is the honest test.
\end{itemize}
\end{frame}

\begin{frame}{Validation: Four Numbers}
\small
\begin{enumerate}
    \setlength{\itemsep}{7pt}
    \item \textbf{Agreement with careful human coding}: accuracy, macro-F1, Cohen's $\kappa$. Read the confusion matrix.
    \item \textbf{Stability}: the same items, a second run.
    \item \textbf{Your own agreement with the coders}, on 15 sentences. If you reach 60\%, a model at 70\% is not bad.
    \item \textbf{The aggregate your paper reports}: each party's share, from the coders and from the model.
\end{enumerate}

\vspace{0.5cm}
{\footnotesize \textbf{The benchmark is a coder, not the truth.} Manifesto coders recoding the same text agreed with the master coding at $\kappa$ of 0.3 to 0.5 on 56 categories (Mikhaylov, Laver and Benoit 2012). Each French election: one coder.}
\end{frame}

\sectionslide{Part 3. A Model on Your Own Machine}{Ollama}

\begin{frame}{Why Run a Model Locally}
\small
\begin{columns}[T]
\column{0.48\textwidth}
\textbf{For}
\begin{itemize}
    \setlength{\itemsep}{5pt}
    \item Confidential data stay on your machine.
    \item Free per call.
    \item You can archive the exact weights.
    \item Temperature and seed work.
\end{itemize}
\column{0.48\textwidth}
\textbf{Against}
\begin{itemize}
    \setlength{\itemsep}{5pt}
    \item Smaller, so less accurate on hard codebooks.
    \item Slower without a good GPU.
    \item Your hardware decides the model.
\end{itemize}
\end{columns}

\vspace{0.7cm}
\centering
The middle way: a large open model on the cluster (Part 4).
\end{frame}

\end{itemize}

\begin{frame}{Alternatives}
\small
\begin{itemize}
    \setlength{\itemsep}{7pt}
    \item \textbf{LM Studio}: an app, a model browser, a server on \texttt{localhost:1234}. No terminal.
    \item \textbf{llama.cpp}: the engine under most of these; serves any GGUF file.
    \item \textbf{MLX}: Apple's framework, the fastest on Apple Silicon.
    \item \textbf{vLLM}: GPU servers, many requests in parallel. For a corpus on the cluster.
    \item \textbf{Hugging Face \texttt{transformers}}: any model, in Python; also to fine-tune your own classifier.
\end{itemize}

\vspace{0.6cm}
\centering
Ollama or LM Studio to start. vLLM when you have a GPU node and a corpus.
\end{frame}

\begin{frame}{Open Weights Is Not Open}
\small
\textbf{Open weights}: you can download and run it. Apache 2.0: Gemma 4, Qwen 3.5, Ministral, gpt-oss. Llama: Meta's own licence.

\vspace{0.4cm}
\textbf{Fully open}: weights, \emph{and} data, code, recipe. \textbf{Apertus} (EPFL, ETH, CSCS; 8B and 70B, Apache 2.0), OLMo.

\vspace{0.6cm}
Why it matters: with the training data public, you can check whether the model saw your corpus. Otherwise you cannot.
\end{frame}

\begin{frame}{Reporting a Local Model}
\small
\begin{itemize}
    \setlength{\itemsep}{7pt}
    \item The tag \emph{and} the digest: a tag can point to new weights tomorrow.
    \item The quantization (\texttt{Q4\_K\_M}): a different quantization is a different model.
    \item Runtime and version, hardware, temperature, seed, context, thinking on or off.
    \item If the paper depends on it, archive the weights file.
\end{itemize}

\vspace{0.5cm}
Part 7 of the notebook writes all of it to \texttt{params.json}.
\end{frame}

\begin{frame}{Why a Cluster}
\small
\begin{itemize}
    \setlength{\itemsep}{6pt}
    \item GPUs: L4 (24 GB), A100 (80 GB), H100, H200. A 27B model on an L4; a 70B on an A100.
    \item Long jobs: a corpus annotated overnight.
    \item Data that must stay at UZH: the model comes to the data.
\end{itemize}

\vspace{0.5cm}
\textbf{Access}: your group's Science IT project; your PI adds you. VPN off campus.

\vspace{0.3cm}
\textbf{Two rules}: login nodes never compute; large files on \texttt{/scratch} (purged after 30 days unused, no backup).

\vspace{0.4cm}
{\footnotesize Every command: \texttt{setup/cluster\_guide.md}.}
\end{frame}

\begin{frame}[fragile]{Door 1. The Terminal}
\vspace{0.1cm}
{\scriptsize
\begin{verbatim}
ssh -l <shortname> cluster.s3it.uzh.ch   # UZH network or VPN
quota                                    # your space
module available                         # the software

# a GPU, interactively
module load l4
srun --pty --time=1:0:0 --mem-per-cpu=7800 \
     --cpus-per-task=2 --gpus=1 bash -l
nvidia-smi             # on a compute node now
exit                   # GPU released

# a job, while you do something else
sbatch annotate.sh     # #SBATCH lines: time, memory, --gpus=1
squeue --me            # PD = waiting, R = running
\end{verbatim}}
\end{frame}

\begin{frame}[fragile]{Door 2. An Agent on the Cluster}
\vspace{0.1cm}
{\scriptsize
\begin{verbatim}
curl -fsSL https://claude.ai/install.sh | bash   # once, login node
claude    # press c, open the URL on your laptop
\end{verbatim}}

\vspace{0.3cm}
\small
Good at: job scripts, submitting, reading logs, relaunching what failed. The well-defined task that can run unattended.

\vspace{0.4cm}
\textbf{Three precautions}
\begin{itemize}
    \setlength{\itemsep}{4pt}
    \item In \texttt{CLAUDE.md}: \textit{``Never run analysis code on the login node; write a job script, submit it with sbatch.''}
    \item Home is shared by all nodes: turn self-updates off (\texttt{DISABLE\_UPDATES}).
    \item VS Code or Cursor: not on the login nodes. S3IT has a recipe through a job.
\end{itemize}
\end{frame}

The door for those who never used a terminal: a Jupyter session with one L4, today's notebook, Part 5.

\begin{frame}[fragile]{A Local Model on a GPU Node}
\small
Inside a GPU session. Apptainer runs the official Ollama image (course recipe; S3IT has no page on LLMs).

{\scriptsize
\begin{verbatim}
module load apptainer
export OLLAMA_MODELS=/scratch/$USER/ollama-models  # on scratch
cd /scratch/$USER
apptainer pull ollama.sif docker://ollama/ollama
apptainer exec --nv ollama.sif ollama serve > ollama.log 2>&1 &
apptainer exec --nv ollama.sif ollama pull gemma4:26b
\end{verbatim}}

\vspace{0.3cm}
Then Part 5 works unchanged on that node. A corpus: the same lines in a batch job. Many requests in parallel: vLLM.
\end{frame}
