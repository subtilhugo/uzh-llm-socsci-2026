\begin{frame}{Last Week, in One Slide}

\small
\textbf{The argument.} An AI system now writes economics papers on its own (APE). Generating a paper is almost free; verifying one is not. The bottleneck moved from \emph{doing} to \emph{judging}, and the chain has to end with a human who understands.

\vspace{0.25cm}

\textbf{The position.} Delegate the work. Keep the skill to check it, and the responsibility for it. Three rules:
\begin{enumerate}
    \setlength{\itemsep}{0pt}
    \item You delegate execution, never understanding.
    \item Read before you accept.
    \item Stop when you no longer know what it is doing.
\end{enumerate}

\vspace{0.25cm}

\textbf{The tool.} A folder that remembers: \texttt{README.md} (what the project is), \texttt{CLAUDE.md} (how the agent behaves), \texttt{PROJECT\_HISTORY.md} (where we stand). Raw data read-only, prompts versioned, every session ends with a commit.

\end{frame}

\begin{frame}{What to Keep in Mind}

\textbf{This is still an open debate.} How much to delegate, and how much to check, is not settled. Reasonable people draw the line in different places.

\begin{frame}{How I Do Not Use AI}

\vspace{0.15cm}

\begin{frame}{Principle 1: You Are in Charge}

\begin{itemize}
    \setlength{\itemsep}{8pt}
    \item Agents overproduce, expand the scope, and overreact to details.
    \item Do not let them run unattended for long (overnight), unless the task is very well defined: for example, monitoring jobs on a cluster and relaunching the ones that fail.
    \item Stay hands-on: in the loop, correcting course, making the judgement calls.
    \item Being hands-on is also how you keep understanding what you are doing, and keep a map of it in your head, even when you no longer write the code.
\end{itemize}

\end{frame}

\begin{frame}{Principle 2: Accuracy, Not Speed or Cost-Cutting}

\begin{itemize}
    \setlength{\itemsep}{8pt}
    \item Run the models at maximum reasoning. For \emph{everything}.
    \item A mistake in a paper costs far more than extra tokens or waiting time.
    \item The difference in intelligence between reasoning levels is large.
    \item More reasoning does not remove the need for verification.
\end{itemize}

\end{frame}

\begin{frame}{A Typical Loop}



\small
\begin{enumerate}
    \setlength{\itemsep}{6pt}
    \item \textbf{Specify the task in writing.} Sample, equation, estimator, clustering, expected output: as in a detailed pre-analysis plan. Germain writes it in Overleaf; you, in \texttt{notes/analysis\_plan.md}.
    \item \textbf{A first agent implements it.} It flags ambiguities \emph{before} coding: there is high value in being on the same page.
    \item \textbf{Other agents review it in a fresh context.} They read the plan, the code and the outputs, and list the discrepancies.
    \item \textbf{You decide what to revise or accept.} A reviewer asked to find problems always finds something. Resolve, rerun, repeat until satisfied.
\end{enumerate}

\vspace{0.2cm}
{\footnotesize Not exotic: Anthropic's own guide to Claude Code recommends the same steps.}

\end{frame}

\begin{frame}{The Typical Failure: Silent Decisions}

A typical failure mode is the AI making consequential decisions without asking. For example, dropping some observations.

\vspace{0.3cm}

\textbf{On data, it looks like this}
\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item rows lost in a merge (inner join instead of left join)
    \item a missing code (\texttt{-9}, \texttt{99}) read as a value
    \item a duplicate removed
    \item an identifier read as a number (\texttt{01001} becomes \texttt{1001})
    \item \chg{missing values treated without asking: blank incomes set to 0, or every respondent who refused dropped. The regression runs on another sample, and the coefficient moves.}
\end{itemize}

\vspace{0.3cm}

\textbf{Two defences}
\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item Every script prints the number of rows before and after each step. A change the plan does not explain stops the agent.
    \item I always ask the reviewing agents to check for this too.
\end{itemize}

\end{frame}

\begin{frame}{Two Phases: Prototyping, Then Sharpening}

\textbf{Prototyping phase:}
\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item It is an exploratory phase.
    \item I do not review the code or the prose.
    \item I treat these outputs as probable but provisional.
\end{itemize}

\vspace{0.4cm}

\textbf{Sharpening phase:}
\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item If I think there is something there, I get involved in the writing and coding process.
    \item I audit the code, paying special attention to the number of rows in the dataset and results that ``look weird''. I have many independent agents check the code.
    \item I rewrite the paper and work with AI to iterate on the visuals.
    \item I take responsibility for the results and claims.
\end{itemize}

\end{frame}

\begin{frame}{What Costs Tokens}

\begin{itemize}
    \setlength{\itemsep}{8pt}
    \item \textbf{\chg{The model has no memory between messages.}} \chg{Each message re-sends everything: the instructions, \texttt{CLAUDE.md}, every file read, every output, every previous exchange. Your 40th message carries the 39 before it.}
    \item \textbf{\chg{The cache makes this re-reading cheaper, not free.}}
    \item \textbf{Effort multiplies tokens}: more files read, more checks, more thinking.
    \item \textbf{A bigger model costs more per turn.}
    \item \textbf{Subagents} spend tokens while you are not typing.
\end{itemize}

\vspace{0.4cm}

\centering
Subscription: tokens are quota. API key: tokens are money.\\
\texttt{/usage} shows where yours went.

\end{frame}

\begin{itemize}
    \setlength{\itemsep}{3pt}
    \item \textbf{\chg{The cache keeps what was already processed}}\chg{, for a while. The timer restarts at every message: one hour on a subscription, five minutes with an API key or once you pay for extra usage.}

\end{itemize}

\begin{frame}{Model and Effort: Two Dials}

\textbf{Model: how capable.} A bigger model understands more: unfamiliar libraries, ambiguous instructions, subtle bugs. It costs more per token.

\vspace{0.3cm}

\textbf{Effort: how thorough.} The same model works longer: it reads more files, thinks more, checks its own work before answering. It costs more tokens.

\vspace{0.5cm}

\textbf{When the answer is wrong, ask which one it is.}
\begin{itemize}
    \setlength{\itemsep}{4pt}
    \item It \emph{did not know}: it misread an ambiguous variable, or did not know how a package behaves. Change the \textbf{model}.
    \item It \emph{did not try}: it skipped a file, did not rerun the code, did not check. Raise the \textbf{effort}.
\end{itemize}

\vspace{0.4cm}

\centering
\texttt{/model} to see and change the model. \texttt{/effort} for the effort:\\
\texttt{low}, \texttt{medium}, \texttt{high}, \texttt{xhigh}, \texttt{max}.

\end{frame}

\begin{frame}{\chg{What ``Thinking'' Means for a Model}}

\centering
\begin{tikzpicture}[font=\scriptsize,node distance=0.5cm]
  \node[draw,rounded corners,fill=gray!15,minimum height=0.9cm,align=center] (q) {\chg{Your\\request}};
  \node[draw,rounded corners,fill=titleblue!25,minimum height=0.9cm,minimum width=4.2cm,align=center,right=0.6cm of q] (t) {\chg{Thinking: text written for itself\\(plan, try, check, correct)}};
  \node[draw,rounded corners,fill=titleblue!70,text=white,minimum height=0.9cm,align=center,right=0.6cm of t] (a) {\chg{Answer}};
  \draw[->] (q)--(t); \draw[->] (t)--(a);
\end{tikzpicture}

\vspace{0.1cm}
\raggedright
\small
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item \textbf{\chg{Thinking is more text, written before the answer.}} \chg{The model works in steps, tries, checks, backs up. The answer follows from that text.}
    \item \textbf{\chg{It is paid like any output.}} \chg{Billed as output tokens, in full, even if the screen shows a summary. It also takes time.}
    \item \textbf{\chg{Effort sets how often and how deeply it thinks.}} \chg{At \texttt{low}, a simple task gets no thinking; at \texttt{max}, as much as needed.}
\end{itemize}

\vspace{0.05cm}

\textbf{\chg{On your data}}
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item \chg{Little thinking: it writes the merge and stops.}
    \item \chg{More thinking: it writes the merge, asks itself how many rows should come out, reruns, and notices the loss.}
\end{itemize}

\vspace{0.15cm}
{\footnotesize \chg{Thinking helps when the model knows enough but must work in steps. It does not add missing knowledge (change the model), nor prove the answer right.}}

\end{frame}

\begin{frame}{Save on Context, Not on Reasoning}

\small
\begin{itemize}
    \setlength{\itemsep}{2pt}
    \item \textbf{One task, one session.} \texttt{/clear} between unrelated tasks costs nothing and loses nothing: the project's memory is in the folder (\texttt{PROJECT\_HISTORY.md}), not in the chat.
    \item \textbf{Watch the first minute.} \texttt{Esc} as soon as it drifts; \texttt{/rewind} to go back. After two failed corrections: \texttt{/clear} and one better prompt, not a third correction.
    \item \textbf{Never paste data.} The agent writes a script that prints summaries (types, counts, missing values); only the summaries enter the context. It also protects confidential data.
    \item \textbf{Point, do not paste.} \texttt{@code/03\_merge.py}, not the file's content. PDFs: only the pages you need.
    \item \textbf{A short \texttt{CLAUDE.md}}: under about 200 lines. Long procedures go in \texttt{prompts/}.
    \item \textbf{A long task:} \texttt{/compact} with a focus (``keep the merge decisions''). Back after more than an hour: a fresh session costs less.
\end{itemize}

\vspace{0.15cm}

\centering
\normalsize
Save on context. Never on reasoning for what enters the paper.

\end{frame}

\begin{frame}{\chg{A Literature Watch, on a Schedule}}

\footnotesize
\chg{\textbf{Every Friday}, a scheduled task searches the web and writes a digest in French, readable in ten minutes. My instruction has five blocks.}

\vspace{0.15cm}

\begin{enumerate}
    \setlength{\itemsep}{2pt}
    \item \textbf{\chg{Cadence check, first.}} \chg{It runs \texttt{date +\%V}: odd week, stop; even week, continue. Weekly trigger, fortnightly digest.}
    \item \textbf{\chg{Context and relevance filter.}} \chg{Who I am, the level of journals, then my current projects described literally and six monitoring axes derived from them.}
    \item \textbf{\chg{Sources.}} \chg{Working papers first (NBER, CEPR, IZA\ldots), then the journals of each field, then preprints.}
    \item \textbf{\chg{Quality bar.}} \chg{``Better six excellent items than thirty mediocre ones.'' Excluded: benchmark-chasing papers, ``we asked GPT-4 to do X'' without human validation, correlations with no identification strategy.}
    \item \textbf{\chg{Output and rules.}} \chg{Must read (5--8): status, link, what it changes for which project, visible weaknesses. Worth noting, one line each. ``Never invent an article or URL. If you cannot confirm an item, remove it.''}
\end{enumerate}

\vspace{0.15cm}

\textbf{\chg{How}}\chg{: Claude Desktop, \textbf{Code} tab, \textbf{Scheduled}, \textbf{New task}. Mine runs in the cloud: it works with the computer off, but cannot see local files. I still click every link.}

\end{frame}

\begin{frame}{\chg{Other Easy Wins for Researchers}}

\begin{itemize}
    \setlength{\itemsep}{6pt}
    \item \chg{\textbf{Before you submit}: rerun the replication package from a clean copy, and check every number in the paper and the slides against the outputs.}
    \item \chg{\textbf{References}: check that every citation in a draft exists and matches its DOI; clean the \texttt{.bib}.}
    \item \chg{\textbf{Referee reports}: one table with every comment, where the revision answers it (page, line), and a draft response that you rewrite.}
    \item \chg{\textbf{Calls and applications}: check a proposal against the call (page limits, required sections, eligibility) before you send it.}
    \item \chg{\textbf{Data releases}: a scheduled task that tells you when a new survey wave or a new election file is published.}
    \item \chg{\textbf{Teaching}: exercises and solutions from your own slides; a check that slides, worksheet and code say the same thing.}
\end{itemize}

\vspace{0.3cm}

\centering
\chg{Same rule as everything else today: the agent drafts, you check.}

\begin{frame}{Scripts, Not Chats}

\begin{itemize}
    \setlength{\itemsep}{6pt}
    \item The agent writes code into the project. It does not answer in the chat: a number in a chat is a claim nobody can rerun.
    \item Every table and figure has a script behind it. \texttt{python3 code/run\_all.py} rebuilds everything from \texttt{data/raw/}.
    \item Coding assistance, three uses:
    \begin{itemize}
        \item Writing: one script per step, each saying what it reads, writes and drops.
        \item Debugging: paste the error, and ask for the cause before the fix.
        \item Documenting: a docstring at the top of each script, the codebook for the variables.
    \end{itemize}
    \item Reading the code stays your job. Ask the agent to explain it.
\end{itemize}

\vspace{0.3cm}

{\footnotesize Developers learning a new library with an AI assistant scored 50\% on a quiz, against 67\% for those coding by hand. Those who asked the AI for explanations scored about as well as by hand (Shen and Tamkin 2026).}

\end{frame}

\begin{frame}[fragile]{Checks to Request}

\small
Silent errors: bad merges, dropped observations, miscoded missing values, mislabelled variables. Three checks catch most of them. Ask for them in the code, not in the chat.

\vspace{0.3cm}

\textbf{Row counts}, before and after every step

{\footnotesize \verb|merge: 1,000 rows -> 980; unmatched: 20 left, 5 right|}

\vspace{0.25cm}

\textbf{Assertions}, which stop the script when they fail

{\footnotesize
\verb|assert df["code_commune"].is_unique|\\
\verb|assert df["code_commune"].str.len().eq(5).all()|\\
\verb|assert df["share_fnrn"].between(0, 1).all()|\\
\verb|assert merged["votes"].sum() == raw["votes"].sum()|}

\vspace{0.25cm}

\textbf{Cross-tabulations}, after every recode and every merge

{\footnotesize
\verb|pd.crosstab(df["q12_raw"], df["q12_clean"], dropna=False)|\\
\verb|pd.crosstab(merged["_merge"], merged["region"])|}

\end{frame}

\begin{frame}{When to Trust, When to Intervene}

\small
\textbf{Trust a step} when a check exists for it, it passed, and you can rerun it.

\vspace{0.2cm}

\textbf{Intervene} when
\begin{itemize}
    \setlength{\itemsep}{1pt}
    \item a number moved and nobody can say why
    \item a match is right on the code and wrong on the territory, the wave or the period
    \item a label says one thing and the code computes another
    \item the result looks too clean
\end{itemize}

\vspace{0.3cm}

\textbf{Audit one step by hand} (prompt 09)
\begin{enumerate}
    \setlength{\itemsep}{1pt}
    \item Choose the riskiest step: a merge, a recode, a filter.
    \item Read its code. Ask the agent to explain each line.
    \item Follow three units from the raw file to the final table: one ordinary, one edge case, one dropped or unmatched.
    \item Read their values in the raw file yourself, and recompute one number by hand.
\end{enumerate}

\end{frame}

\begin{frame}{Block 3. Audit and Decide (11:15--11:45)}

\small
\textbf{I show (10 min).} I close the session and open a fresh one. Prompt 08: a reviewer that did not see the code being written. Then prompt 09: I audit one step by hand, three municipalities that became one.

\vspace{0.3cm}

\textbf{You do (15 min)}
\begin{enumerate}
    \setlength{\itemsep}{3pt}
    \item Close the session. Open a new one. Prompt 08. It runs for several minutes: do not wait.
    \item Prompt 09 on that step, in a second session. Read three units in the raw data yourself. \alert{Not optional.}
    \item For each point of the review and of your audit: fix it, or accept it and write down why. Rerun \texttt{code/run\_all.py}.
    \item Prompt 05: the entry in \texttt{PROJECT\_HISTORY.md}, and the commit.
\end{enumerate}

\vspace{0.3cm}

\textbf{We check.} That is the debrief.

\end{frame}
